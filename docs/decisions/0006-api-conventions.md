# 0006 — API conventions

**Status:** Accepted (2026-10-19)

## Decision
- **Versioning:** URL prefix `/api/v1/`. Breaking changes go to `/api/v2/`.
- **Paths** end with `/` (Django convention).
- **Auth default:** every endpoint requires authentication unless it explicitly opts out
  (only health checks do today).
- **Format:** JSON only (browsable API in development only). Page-number pagination,
  25 per page.
- **Errors:** one envelope for all errors:
  `{"error": {"code": str, "message": str, "details": any|null, "request_id": str}}`.
  `code` is machine-readable (`validation_error`, `not_found`, `permission_denied`,
  `not_authenticated`, `server_error`, ...). Validation errors put field errors in
  `details`. Unhandled exceptions return a generic 500 and are logged server-side.
- **Request IDs:** `X-Request-ID` is echoed (if it matches `[A-Za-z0-9._-]{1,64}`) or
  generated, and returned in every response and error body.
- **Contract:** `docs/api/openapi.yaml` is generated by drf-spectacular and committed;
  CI fails when it is stale. The live schema endpoint is staff-only outside development.
- **Long-running operations** return `202` with a resource ID and a status endpoint
  (from Phase 3 on).
- **Consequential external effects** accept an idempotency key (from Phase 7 on).
